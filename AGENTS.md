# AGENTS.md — Contributor & Autonomous Agent Guidelines

Welcome to the **Hardware-Backed mTLS Proof of Concept (PoC)** codebase. This document outlines architectural invariants, development conventions, security boundaries, and step-by-step guidance for human developers and autonomous AI agents working in this repository.

---

## 🎯 Project Mission & Architectural Philosophy

The objective of this repository is to demonstrate zero-trust client-to-cloud security on Android:
1. **Hardware-Anchored Identity**: Cryptographic identity resides solely in secure hardware (StrongBox HSM or ARM TrustZone TEE).
2. **Cryptographic Proof of Genuine Hardware**: The backend verifies device provenance via Google's Remote Key Attestation extension before trusting any device public key.
3. **Non-Exportable Keys**: Private keys can **never** be extracted, exported, or handled by application code.
4. **Mutual TLS 1.3 Handshakes**: Transport layer security is anchored directly to the hardware key.

---

## ⚠️ Critical Security Invariants (DO NOT VIOLATE)

When making modifications or adding new features, all agents **must strictly adhere** to the following invariants:

1. **Zero Private Key Exposure**:
   - Never attempt to call `.encoded` on `PrivateKey` instances returned by `AndroidKeyStore`. Hardware keys do not expose raw bytes.
   - All cryptographic operations (signing, handshake challenge verification) must delegate directly to the JCA `AndroidKeyStore` provider or through `AndroidKeystoreSigner`.
   - Never serialize private key handles into SharedPreferences, DataStore, files, logs, or network payloads.

2. **Nonce Replay Protection**:
   - Never omit or hardcode the challenge nonce during key generation.
   - Attestation challenges generated by the backend must be fresh, cryptographically random, single-use, and time-bounded (`expires_in`).

3. **StrongBox with Resilient TEE Fallback**:
   - Always attempt `setIsStrongBoxBacked(true)` when `PackageManager.FEATURE_STRONGBOX_KEYSTORE` is present.
   - Always handle `StrongBoxUnavailableException` (or equivalent manufacturer exceptions) by gracefully falling back to standard `TEE` (see [KeystoreManager.kt](file:///Users/kypeli/src/own/mtls-poc/android/app/src/main/java/com/kypeli/mtlspoc/security/KeystoreManager.kt)).
   - Do not crash or block execution if a device lacks StrongBox support.

4. **TLS 1.3 Strictness**:
   - Client and backend communication for the protected endpoint should mandate TLS 1.3 (`TLSv1.3`).
   - Custom `X509ExtendedKeyManager` implementations must supply the correct hardware alias during client alias resolution.

## 📦 Dependency Management Rules

- **Gradle Version Catalog**: All dependencies must be declared in [libs.versions.toml](file:///Users/kypeli/src/own/mtls-poc/android/gradle/libs.versions.toml).
- Never hardcode dependency coordinates or versions inside `build.gradle.kts`.
- Current core library stacks:
  - **Networking**: OkHttp 4.12.0 + Moshi Kotlin 1.15.2
  - **Cryptography**: Bouncy Castle `bcpkix-jdk18on` + `bcprov-jdk18on` 1.78.1
  - **UI**: Jetpack Compose BOM `2026.02.01`, Material 3
  - **Concurrency**: Kotlinx Coroutines 1.8.1

## ✅ Completed Tasks

### Backend Service (`backend/`)
- **Status**: Fully implemented in Go (`cmd/server`, `cmd/certgen`, `internal/`).
- **Features**:
  - Dual listeners: `:8080` (HTTPS Standard TLS Enrollment & Challenge) and `:8443` (Strict Mutual TLS 1.3).
  - Google Hardware Attestation Root CA trust pool & OID `1.3.6.1.4.1.11129.2.1.17` ASN.1 parser.
  - In-process ECDSA P-256 Certificate Authority with PKCS#10 CSR validation and client certificate signing.
  - Ephemeral challenge store (single-use, monotonic TTL) and device registry.
  - Test suite with 100% pass rate (`make test`).
